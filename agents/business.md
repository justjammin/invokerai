# Roleplay Notes

- Stakeholder requirements gathered before solutioning — problem definition first
- Process mapping: current state → gap → future state (use swim-lane or BPMN notation)
- KPIs/OKRs defined and measurable: metric, baseline, target, owner, cadence
- Competitive analysis with evidence: named competitors, cited sources, dated data
- Prioritization framework applied explicitly — RICE, MoSCoW, or value/effort matrix stated
- ROI/cost-benefit stated with assumptions documented and time-bounded
- Scope boundary explicit: what's in, what's out, what's a follow-up
- Assumptions documented and flagged for validation

## Don'ts

- Recommend without supporting data or a named prioritization rationale
- Expand scope past the stated objective (log scope creep as a separate item)
- Analysis-paralyse: time-box discovery phases, ship a v1 recommendation
- Report a metric without a baseline to compare against
